|---|---|---|---|
| D01 | Use Help Desk Tickets v3 as primary discovery data | BPI 2014, UCI enriched incidents, BPI 2013; see dataset-selection.md | Linked operational history plus a real conversation sample. Accept cohort/time-coverage work and limited text. Revisit if valid support cohort fails. |
| D02 | Complete selection and initial profile before application work | Predetermined routing/RAG build rejected by project brief | Protect data-before-story sequence. AI use case remains undecided. |
| D03 | Preserve raw bytes and source metadata; separate layers | Ad hoc edits to a single CSV | Publisher checksum verification provides provenance. More explicit storage, less ambiguity. |
| D04 | Use Python profiling plus SQL integrity queries in SQLite | All-Python joins, premature PostgreSQL deployment | Repeatable relational logic without server overhead. SQLite is only the profiling engine, not the final platform database decision. |
| D05 | Exclude cases with tied status timestamps from preliminary transitions | Guess order using row/ID order | Conservative initial evidence; excluded cases must be revisited using change semantics. |
| D06 | Do not equate elapsed time or ownership time with effort | Direct hours-saved calculation | No observed labor-time evidence. Future impact estimates need explicit assumptions. |
| D07 | Retain dataset attribution separately from future code license | Assume every public dataset is CC BY | Mendeley CC BY 4.0; inspected BPI repository records list 4TU terms. No redistribution decision or legal interpretation made. |
| D08 | Primary discovery scope: external-project Ticket, creation from 2019-01-01 | Whole history; starts 2016–2020; broader Ticket/Service/HD Service. See cohort-sensitivity.csv and resolution-date concentrations | First full year after concentrated 2018 resolutions, without filtering on future outcome or trimming long cases. Earlier/broader cohorts retained for sensitivity. Not a universal incident taxonomy. |
| D09 | Collapse equivalent simultaneous values, quarantine conflicting field histories | Milestone 1 excluded every tied case | 85 duplicate observations; only 9 status-conflicted cases and 1 assignee-conflicted case across all data. Preserve contributing IDs. Different-field simultaneous events are allowed. |
| D10 | Use observed intervals with an unknown initial prefix | Backfill Open or first assignee from creation | Primary initial status gap median 108 seconds. Publisher summaries backdate ownership in 37,389 cases. Avoid claiming unobserved facts. |
| D11 | Separate recorded resolution, first Resolved entry and source endpoint | One generic MTTR | 6,875 primary cases have first Resolved entry and recorded resolution >60 seconds apart. Definitions and denominators remain explicit. |
| D12 | Use SQL consumer views for metric eligibility | Let every downstream analysis select its own exclusions | Status 17,132; assignment 16,379. Invalid values are NULL, valid observed zeros remain zero. Preserve entire export in diagnostics. |
| D13 | Bound future text experiments to the available sample | Treat utterances as independent test cases or extrapolate to full history | 360 issues, all created 2022; 340 primary. Prospective labels and intervention still undecided. |
| D14 | Prioritize long/repeated Waiting for root-cause validation | Validation returns, prolonged Resolved state, reopening, multiple handoffs | Waiting is 41.96% of observed time and remains 41.31% after excluding top ten contributing projects. Repeated-wait cases are 7.58% of status cohort and 25.18% of waiting time. Causes and preventability remain unproven. |
| D15 | Keep validation returns as the alternative candidate | Select solely by largest duration association | Validation-return association is larger but 545/672 cases are in 2019–2020. Temporal concentration and lower current text coverage weaken it as the first validation target. |
| D16 | Report exploratory associations and sensitivity without causal or savings claims | Interpret median gaps as treatment effects | Retrospective exposure, missing outcomes, shared duration definitions and confounding prevent causal interpretation. Case/project bootstrap and overlap-stratum coverage are disclosed. |
| D17 | Do not treat the text sample as representative | Similar priority mix might suggest representativeness | Repeated Waiting is 16.8% in primary text sample vs 6.0% of eligible 2022 tickets. Review reasons within sample; no direct population extrapolation. |

| D18 | Milestone 4 outcome C: no addressable operational problem established | Compared concentrated Waiting, validation returns and diagnostic-information/dependency coordination; see problem-validation.md | Specific dependencies and active work occur in Waiting; return transitions include successful-test deployment. Observed timing does not establish feasible earlier action or independent harm. |
| D19 | Preserve qualitative review as provisional evidence with exact lineage | 32 purposive episodes, two expanded; 12 validation-return events in nine text-covered cases | Biased text sample and masked/off-platform context prevent prevalence or ground-truth claims. Pinned packet hashes require re-review if evidence changes. |
| D20 | Use first positive episode for antecedent and downstream comparisons | Episode-weighted comparisons and full-case duration gaps | One actual row per case preserves unknown boundaries. Later outcomes are separated from prefix events; source endpoints still do not establish complete follow-up. |
| D21 | Defer every intervention comparison until business-problem validation | Milestone 3's early shortlist | Picking a fix before the problem is validated would be backwards. No redesign, deterministic-rule, traditional-automation or AI evaluation and no savings estimate in Milestone 4. |

Measured descriptive baseline established; addressable business problem, intervention, model choice, operational thresholds, automation authority, application stack, cloud design and cost remain undecided. D18 supersedes D14's provisional candidate priority; D21 supersedes earlier intervention shortlists.
