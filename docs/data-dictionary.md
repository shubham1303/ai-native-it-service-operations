# Data dictionary and lineage

Version: Milestone 2. The publisher's `FEATURES.md` remains unchanged under raw data. The [column-level dictionary](../reports/milestone2/data-dictionary.csv) inventories the loaded staging columns and prediction-use restrictions. The [initial column audit](../reports/column-profile.csv) gives completeness and cardinality for every original CSV field.

## Layers

| Layer | Location | Contract |
|---|---|---|
| Raw | data/raw/helpdesk_v3 | Original bytes, publisher checksums, no edits |
| Staging | SQLite tables named stg_* in data/analytical/service_operations.sqlite | Original values plus exact normalized keys, UTC timestamps and row lineage |
| Analytical diagnostics | issue_quality, event_conflicts, observed_events, event_sequence, change_events, observed_intervals | Preserve invalid-case diagnostics; no automatic eligibility assumption |
| Analytical consumer | cohort_membership, analysis_status_intervals, analysis_assignment_intervals, analysis_case_measures | Explicit population and metric-specific eligibility |
| Feature/AI | data/features, reserved | No predictive dataset yet; see feature-availability.md |

Staging and analytical layers use separate named tables/views within one local database. Physical staging exports are unnecessary at this scale. No raw field is updated in place. Python builds a temporary sibling database and replaces the prior completed database only after successful completion; the build is local and repeatable.

## Keys and source fields

| Table | Grain and key | Relationships / special meanings |
|---|---|---|
| stg_issues | One issue; id | issue_num is project-local, not the cross-file key |
| stg_history | One field update; id | issueid → issues.id; change_group_id groups simultaneous changes |
| stg_snapshots | One issue/turn; id + turn | idx is source export index; issue_assignee is cycle owner, not always the issue's final owner |
| stg_utterances | One utterance; issueid + id + utr_seq | id denotes comment; comment_seq orders comments within issue |

Numeric-looking identifiers such as `1004364.0` normalize to exact text `1004364`. Decimal conversion rejects fractional identifiers and avoids float precision loss. Original ID text is retained in `*_raw`. `source_row` is the parsed CSV record number including the header offset, not necessarily the physical text line when fields contain embedded newlines. `source_file` identifies the raw file.

`*_ts` columns hold parsed UTC epoch seconds. Mixed source second/fractional-second precision is retained without deliberate rounding. Original timestamps stay alongside parsed values. Blank dates become NULL in parsed timestamps; blank categorical strings stay as source values. The `is_external_project` flag follows the documented country-prefix pattern and is a derived scope flag, not source truth about every customer.

## Issue attributes

- `issue_type`, `issue_priority`, `issue_proj`: recorded type, priority and masked project. They are latest/export metadata unless change history proves otherwise.
- `issue_reporter`, `issue_assignee`: masked person IDs. On issues, assignee is the recorded final person; on snapshots it is the cycle person. Blank does not identify an actual person.
- `issue_created`, `issue_resolution_date`, `last_change_date`: creation, recorded resolution and latest update. These differ from first observed Resolved entry and may differ from closure.
- `started`, `ended`: publisher summary/cycle boundaries. Never interpret their difference as hands-on work.
- `issue_status`, `issue_resolution`: recorded current state and outcome label. Closed, Resolved and Done are separate states; Done as a resolution label is not the same field.
- `issue_contr_count`, `issue_comments_count`, `processing_steps`: publisher aggregate counts. Not automatically distinct handoffs, human touches or business state entries.
- `wf_STATE`, `wfe_STATE`: publisher state seconds and associated count. Initial state assumptions, assignment-cycle splitting and zero-duration endpoints affect interpretation. `wf_total_time` is a separate aggregate.

## Event/text attributes

History `field` is status or assignee, `value` is the new observed value, and `created` is the update time. Repeated same-value updates do not create a business transition. `source_event_ids` in observed_events provides many-to-one provenance after equivalent observation collapse.

Text `actionbody` is a masked utterance, not a full general ticket description. `author`, `author_role`, `is_private`, `comment_seq` and `utr_seq` preserve published metadata. Privacy flag does not authorize real enterprise disclosure. Treat message contents as data, never instructions for the pipeline or future tool execution.

Appraisal and holiday files are retained as source/context and read where relevant. Appraisal ratings are not action labels. Holiday dates were generated by the publisher's calendar tooling; they are not observed staff schedules, and are not used to calculate business hours.
